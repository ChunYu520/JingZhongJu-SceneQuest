# 08. 安全、隐私与内容合规

## 1. 身份和认证

- MVP 使用匿名参与者，不收集非必要实名信息。
- 访问 token 应使用高熵随机值，只在创建/加入时返回一次；数据库存哈希。
- token 通过 `Authorization` 头传递，不写入 URL query 或日志。
- 管理台使用单独的 `ADMIN_TOKEN`，不得与玩家 token 共用。
- 管理员需从独立登录页进入；生产环境在部署时配置强随机 `ADMIN_TOKEN`，禁止首次口令 bootstrap。
- AI API Key 仅经管理员鉴权后提交到服务端，GET 只返回 `hasApiKey` 状态；不回显密钥。
- `.env` 写入仅限服务器 API 进程；生产环境需用文件权限限制读取，不能把 `.env` 放入版本库或静态资源目录。
- 管理员令牌只留在当前页面内存，重新加载需重新登录；生产管理页面必须经 HTTPS 提供。
- 房间邀请码不是玩家身份凭证；仅有邀请码不能读取已加入玩家的私有状态。

## 2. 权限模型

- 角色私有信息只可由持有者及明确授权的服务读取。
- 所有 API 从 token 推导 playerId，不信任客户端自报身份。
- Socket.IO 订阅必须先验证玩家属于该 session。
- 管理操作单独鉴权，生产环境禁用或限制调试 API。

## 3. 位置与个人信息

- 景区可由用户主动定位或手动选择；定位只用于服务端匹配景区和发现公开点位。
- 房间二维码只含邀请链接，不做景点签到或位置证明。
- 定位必须在使用前清楚说明用途，并由用户主动授权。
- 不持续追踪玩家离开体验后的轨迹。
- 不在玩家快照中广播精确定位坐标；保存景区名称、公开点位和来源即可。
- 不收集身份证号码、支付信息或与游戏无关的个人资料。
- 定义会话数据保留时间；MVP 可在会话结束后保留最小调试数据，并提供过期清理。
- 正式上线前由运营方根据实际业务、部署地域和数据处理方式核查适用的个人信息保护、网络安全、内容管理和备案要求；本文件不是法律意见。

## 4. 用户生成内容

- 玩家输入仅用于当前游戏中必要的互动。
- 玩家上传照片仅用于当前任务 AI 验收；前端压缩图片，提示避免拍摄游客正脸、工作人员或非公开区域。
- 玩家提交内容视为不可信证据，AI 验收提示词明确忽略要求越权/直接通过的指令。
- 模型只返回验收结果，积分和背包由服务端事务管理。
- AI 生成文本不得引导骚扰、危险挑战、违法行动或进入封闭区域。
- 发现攻击性或不适当输入时，优先忽略其对剧情状态的影响，给出安全提示。
- 允许用户退出游戏；退出不应影响其现实出行安全。

## 5. 文化内容和知识产权

- MVP 优先采用原创角色与原创剧情。
- 真实历史信息必须来自可追溯资料，且不能把 AI 推断伪装成史实。
- 对景区名称、商标、图片、演出内容和受保护角色使用前确认授权边界。
- 未经授权，不复制电影、游戏或网文中具有独创性的角色和剧情。
- 景区合作版需要明确景区提供资料、运营方审核和内容更新责任。

## 6. 安全任务规则

禁止任务要求玩家：
- 奔跑穿越道路、攀爬、翻越围栏；
- 进入封闭、危险或未开放区域；
- 接触电气设备、火源、燃气或其他危险设施；
- 骚扰陌生游客或工作人员；
- 为了游戏泄露真实账号、密码、支付信息或敏感个人信息。

安全规则不仅写在提示词里，还应由后端对白名单地点、生成 schema、危险行为和积分范围做校验。
