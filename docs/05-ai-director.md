# AI 景区研究、编剧与任务验收

## AI 的职责

AI 负责从景区公开资料中发现可用地点，创作本局全部剧情内容，并按每项任务的验收标准判定玩家提交的照片/文字。服务端负责校验 schema、安全边界、任务唯一性、积分和兑换账本。

## 景区资料发现

`venue-discovery.js` 接收景区名称/城市或授权定位坐标：

1. 通过 Nominatim 进行景区地理编码（手动输入时）。
2. 通过 Overpass 查询附近公开景点、历史标记、观景点、文化设施等 OpenStreetMap 要素。
3. 可选 Tavily 搜索公开网页补充背景资料。
4. 将候选地点、检索摘要和来源链接交给 AI。

位置结果缓存 10 分钟。没有足够公开地点时返回错误，不伪造点位。浏览器不直接保存或展示 API 密钥。

## 完整剧本生成

AI JSON 契约包含：

- 故事标题、谜题、开场、基调、结局；
- 3–5 个角色及目标；
- 搜索结果中的地点与现场提示；
- 3–8 个任务：标题、行动说明、地点、证据提示、验收标准、积分、补充提示；
- 私有线索标题和正文。

Zod 校验字段和长度；地点白名单阻止虚构点位；安全过滤拒绝危险行动。验证失败或 AI 未配置时不发布故事。保存后故事随房间创建发给全部玩家，角色和私有线索继续按玩家权限返回。

## 任务判定

玩家通过 `POST /sessions/:id/tasks/:taskId/submissions` 提交描述和可选图像。后端调用 `judgeTaskSubmission`，向模型提供本任务隐藏验收标准、地点、玩家描述和图像。输出结构为：

```json
{"approved":false,"confidence":0.42,"feedback":"请补充能辨认地点的现场照片。"}
```

只有模型明确通过且置信度达到阈值时，服务端才在事务中标记该玩家的任务完成并按剧本给分。重复请求、模型失败、证据不明确都不重复发奖。

图片输入使用 `AI_VISION_MODEL`（空值时回退 `AI_MODEL`），需选择支持图像输入的模型。API key 仅放在服务端 `.env`。

## 奖励与可信状态

- 积分值来自已验证的 AI 剧本，经过 5–100 分边界校验。
- AI 只返回验收结果，不能直接改数据库积分或背包。
- 积分加减和兑换由后端在数据库事务中执行。
- 房间邀请二维码只编码加入 URL；不设计景点签到二维码。
