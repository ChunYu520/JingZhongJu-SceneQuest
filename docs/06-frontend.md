# 前端流程与交互

## 页面流程

1. 首页：开始创建 / 加入房间。
2. 创建：主动授权定位附近景区，或手动输入景区名/城市；填写玩家昵称。
3. 生成中：显示正在搜索公开资料、生成故事和任务。
4. 大厅：显示房间码、分享链接、房间邀请二维码、玩家列表和剧本标题。
5. 游戏：AI 发布的当前任务、目标地点、证据提示、积分值、我的角色/积分/背包、全队积分榜。
6. 任务提交：拍照或填写文字后提交，展示 AI 验收中、通过加分或补充证据反馈。
7. 兑换商店：显示道具价格、积分余额；成功兑换后更新背包。
8. 结局：所有任务完成后展示 AI 生成结局和个人积分。

## 定位与手动选择

- 页面首次打开不请求位置。
- 点击“定位附近景区”才弹出浏览器定位授权；授权后用反向地理编码预填名称/城市，用户可以改正。
- 手动输入景区名同样可创建，服务端自动地理编码和查询公开点位。
- 不提供人工输入任务点位或故事内容的表单。

## 邀请房间

- 房间大厅展示邀请码和分享链接；二维码编码 `/?join=<inviteCode>`。
- 扫码打开加入页，邀请码自动填充，玩家输入昵称加入。
- 游戏任务不显示扫码签到功能，也不把景点二维码当作任务验证。

## 游戏和积分

- 只渲染服务器快照；任务提交前不得自行展示完成状态。
- 任务卡展示目标地点、AI 生成的发现提示和可得积分。
- 图片在浏览器缩放/压缩后再提交，后端限制 JSON 图像体积。
- 展示个人积分、队友公开积分榜、个人兑换背包。
- 只有 API 明确返回验收通过/兑换成功后才更新界面；失败时保留反馈并允许重新提交。

## 隐私

- 明确说明定位用途；不请求后台持续定位。
- 提醒不要拍摄游客正脸、工作人员或非开放区域。
- API key 从不进入浏览器代码或浏览器存储。

## 管理员后台

- 右上角进入管理员控制台；首次本地开发可创建管理员口令，之后登录验证。
- 设置 AI Provider、API Base URL、API Key、文本/视觉模型以及可选的 Tavily 和 OpenStreetMap 搜索参数。
- 密钥输入框不回填已有密钥，页面只显示是否已配置；空白保存保留原值。
- 完整后端将设置写入服务端 `.env` 并即时应用；本地免依赖预览会标出设置仅在当前进程生效。
- 支持调用 AI 接口连接测试与读取当前房间诊断。
